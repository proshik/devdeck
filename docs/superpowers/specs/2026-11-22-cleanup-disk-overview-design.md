# Страница «Очистка»: обзор диска Mac и разделы движков

Дата: 2026-11-22 · ветка `cleanup-disk-overview` · статус: черновик на согласование

Документ один: дизайн и план задач (в конце). Отдельного файла в `docs/superpowers/plans` нет.

## 1. Намерение и зачем

22.11 диск Mac был заполнен на 90% (797 / 926 ГБ). Ручной разбор показал: основная масса —
Rust `target/` в проектах и старых review-клонах (~420 ГБ), кеши (`~/Library/Caches` 39 ГБ,
`~/.cache` 32 ГБ, `go/pkg` 8 ГБ, `.gradle` 5 ГБ, `~/.minikube/cache` 4.6 ГБ, Xcode 7.5 ГБ) и файл
диска VM colima на стороне Mac (`~/.colima/_lima/_disks/colima/datadisk`, 91 ГБ занято из 100).

Сейчас страница «Очистка» разбирает только docker внутри colima и внутри ноды minikube. На вопрос
«куда делся диск Mac» она не отвечает и чистить его не умеет. Нужно, чтобы она отвечала на этот
вопрос сверху и давала безопасно освободить известные пересоздаваемые данные (сборки, кеши), а
docker-очистки остались ниже — по одному разделу на каждый установленный движок.

Успех: открыв страницу и нажав «Сканировать», пользователь за несколько минут видит, сколько занято
на диске Mac, какие сборки/кеши можно удалить (с размером и временем последнего изменения) и где
лежит остальное; отмечает нужное и одной кнопкой освобождает место, не рискуя удалить что-то
кроме показанного.

## 2. Цели, не-цели, анти-цели

**Цели**

- Общий раздел «Диск Mac» вверху страницы: полоса занятости тома с домашней папкой.
- Сканирование домашней папки по кнопке: прогресс, отмена, запомненный результат с датой.
- Известные категории — чекбоксы, сумма выбранного, удаление с подтверждением.
- Крупнейшие папки — размер, раскрытие вглубь, «Показать в Finder»; без удаления.
- Ниже — разделы Colima, Docker Desktop, Minikube, каждый виден, если программа установлена.

**Не-цели (явно отказались)**

- fstrim / «вернуть место macOS» из диска VM.
- Удаление клонов и worktree, перенос в Корзину.
- Запрос Full Disk Access или любых других прав; недоступное считается частичным и помечается.
- Новые настройки, автоматическое/фоновое сканирование, расписания.
- Изменение порога подсказки «Диск VM почти заполнен» в поповере.
- Удаление «неизвестных» папок и файлов дисков VM с этой страницы.

**Анти-цели (провал, даже если «работает»)**

- Удалено что-то кроме путей, перечисленных в подтверждении, или путь вне домашней папки.
- Удалён `target` идущей прямо сейчас сборки без предупреждения.
- Обход ушёл по симлинку наружу или на другой том, либо двойной счёт hardlink'ов раздул цифры.
- Сломано текущее поведение docker-разделов: оценки, test containers, уникальность `RowID`
  строк в `Form`, лог последнего запуска, перезапуск colima.
- Страница тормозит/блокирует главный поток при сканировании или при открытии.

## 3. Ограничения

- Архитектура проекта (`CLAUDE.md`): любой процесс — синтетическая `Command` через общий runner
  (`zsh -lc`), вывод в «Логи», состояние в общем state machine. Удаление — тоже так.
- Probe pattern: всё внешнее (файловая система, статистика тома, присутствие программ) — за
  протоколом; юнит-тесты не трогают реальные пути, процессы и сеть.
- Сканер — обход на Swift внутри приложения, без `du`-подпроцесса и без сторонних библиотек.
- Стиль страниц главного окна (как «General»): `Form` + `.formStyle(.grouped)`, `FormFooter`,
  `FormActionRow`, `FormNavigationRow`, управляющие кнопки — в toolbar окна; без таблиц и
  сегментных контролов посреди страницы. Все строки — EN и RU в `L10n`.
- Приложение без sandbox. Docker Desktop на машине разработчика не установлен — его часть
  проверяется только тестами с фейками.
- Файлы DevDeck на диске — через `PrivateFile` (0600 / 0700): результат сканирования содержит
  пути пользователя.

## 4. Подходы

### 4.1. Как считать размеры (выбрано пользователем)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Обход на Swift внутри приложения за протоколом** (выбран) | тестируется на фейковом дереве; полный контроль: не идти по симлинкам, не выходить за том, allocated size, hardlink один раз; прогресс и отмена — естественно | писать и сопровождать свой обход |
| `du -sk`/`du -d N` подпроцессом | готово, быстро написать | нет прогресса и честной отмены по ходу; разбор вывода; поведение с hardlink/томами зависит от флагов; не тестируется без процесса |
| Сторонняя библиотека | — | зависимость ради одного обхода; запрещено заданием |

### 4.2. Как удалять (выбрано пользователем)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Синтетическая `Command` с `rm -rf` по путям через общий runner** (выбран) | вывод в «Логи», состояние и блокировка кнопок как у docker-очисток; один механизм процессов | нужна аккуратная сборка shell-строки (`shellQuote`) и проверки в самой команде |
| `FileManager.removeItem` в процессе | без shell | второй движок «процессов» без логов и состояния; долгое удаление на главном акторе или отдельная своя машинка состояний |
| Перенос в Корзину | обратимо | пользователь отказался: место не освобождается до очистки Корзины |

### 4.3. Как показывать (выбрано пользователем: вариант «C», гибрид)

Сверху — список известных категорий с чекбоксами и одной кнопкой «Очистить выбранное · N ГБ»,
ниже — «Крупнейшие папки» с раскрытием. Отвергнуты: только дерево папок (непонятно, что можно
удалять безопасно) и только список категорий (не отвечает «куда делся диск»).

### 4.4. Решения внутри выбранного подхода (мои)

- **Чтение каталога в live-реализации** — через `getattrlistbulk(2)` (один вызов на пачку
  записей с типом, allocated size, dev/ino, nlink, mtime) или `opendir`+`lstat`; выбор — за
  исполнителем по замеру, семантика одна (см. §5.4). `FileManager.enumerator` не подходит:
  медленнее и неудобно отменять/отделять ошибки доступа.
- **Модель отдельная**: `DiskOverviewModel` рядом с `CleanupModel`, а не расширение последнего —
  у сканирования свой жизненный цикл (идёт минуты, отменяется, запоминается), docker-часть не
  меняется по смыслу.

### 5.2. Диск Mac

- Занято / всего / процент для тома, на котором лежит домашняя папка (на Mac — Data-том APFS).
  «Занято» = ёмкость − доступно (`volumeTotalCapacity`, `volumeAvailableCapacity`; не «для
  важного использования», чтобы не путать с purgeable). Формат и цвета — как у полосы диска VM
  (`VMDiskInfo.format()` и `pressureColor`).
- Читается при открытии страницы, по «Обновить» и после завершения удаления. Без процессов,
  без сканирования. Probe за протоколом (`VolumeUsageProbing`).

### 5.3. Сканирование

- Только по кнопке «Сканировать» в toolbar. При открытии страницы не запускается.
- Во время скана: в разделе «Диск Mac» строка прогресса — файлов просмотрено, байт насчитано,
  текущая папка верхнего уровня; кнопка toolbar превращается в «Остановить». Обновление
  прогресса на главном акторе не чаще ~4 раз в секунду.
- Отмена: прерывает обход в течение долей секунды; прежний результат (если был) остаётся на
  экране, новый неполный не сохраняется.
- Завершённый результат сохраняется в `disk-scan.json` в каталоге данных DevDeck
  (`PrivateFile`, 0600) и показывается после перезапуска приложения с датой сканирования — до
  следующего скана. Битый/несовместимый файл — игнорируется (как будто скана не было).
- Скан и удаление взаимоисключаются: во время удаления (и любой другой cleanup-команды)
  «Сканировать» недоступна; во время скана недоступна «Очистить выбранное».
- Кнопка «Обновить» (как сейчас) перечитывает диск Mac, диски VM и docker-цифры; скан она
  не запускает.

### 5.4. Правила обхода

- Корень — домашняя папка (`NSHomeDirectory()`).
- **Симлинки не разворачиваются**: симлинк учитывается как сам файл-ссылка, внутрь не идём.
- **Том не покидаем**: каталог с другим `st_dev`, чем у корня, не обходится (смонтированные
  тома, сетевые папки, firmlink'и на другие тома).
- **Размер — фактически занятое место** (allocated: `st_blocks × 512` или
  `ATTR_FILE_ALLOCSIZE`), а не логический размер: sparse-файл диска VM считается как 91 ГБ, а
  не 100.
- **Hardlink'и — один раз**: файл с `nlink > 1` учитывается при первой встрече по паре
  `(dev, ino)`. Известное ограничение: клоны APFS (`cp -c`) считаются полностью, обход их не
  различает — так же делает `du`.
- **Недоступное — частично**: ошибка доступа (EACCES/EPERM) на каталоге — каталог помечается
  «недоступно», его размер не известен; результат помечается «частично», под полосой —
  «частично: N папок недоступны» с раскрытием списка. Никаких запросов прав.
- **Защищённые папки macOS не обходятся** (решение пользователя, §8.1): `~/Desktop`,
  `~/Documents`, `~/Downloads`, `~/Library/Mobile Documents` (iCloud Drive),
  `~/Library/Containers`, `~/Library/Group Containers`. Сканер в них не заходит (ни `opendir`,
  ни `stat` содержимого), чтобы macOS не показывала окно-запрос. На странице они видны строками
  «не просканировано — защищено macOS» без размера; результат из-за них «частичным» не
  считается (это отдельная пометка, не ошибка доступа). Список — константа рядом со сканером,
  покрыт тестом.
- Для каждого каталога считаются: занятый размер поддерева, число файлов и **время последнего
  изменения поддерева** — максимум `mtime` по всем файлам и каталогам внутри (mtime самого
  каталога `target` при сборке почти не меняется, поэтому нужен максимум).
- Обход не на главном акторе (`Task.detached`, priority `.utility`), проверка отмены — на каждом
  каталоге.

### 5.5. Распознавание известных категорий (чистая функция)

Категория распознаётся во время обхода по имени каталога и именам его соседей/известному
пути. **Внешняя категория побеждает**: внутри найденной категории вложенные не ищутся
(`node_modules` внутри `node_modules`, `target` внутри `~/.cache` и т.п. не дают отдельных
строк), но размер считается полностью.

| Категория | Как распознаётся | Как удаляется | Цена (текст в строке) |
|---|---|---|---|
| Rust `target` | каталог `target`, у родителя есть **файл** `Cargo.toml`; внутри самого `target` **нет** `Cargo.toml` и `.git` | `rm -rf` каталога | пересборка проекта с нуля |
| `node_modules` | каталог `node_modules`, у родителя есть файл `package.json`; внутри нет `.git` (см. ниже) | `rm -rf` каталога | `npm/pnpm/yarn install` заново |
| `~/Library/Caches` | точный путь | содержимое, сам каталог остаётся | приложения пересоздадут; лучше закрыть браузеры/IDE |
| `~/.cache` | точный путь | содержимое | повторная загрузка (могут быть модели, напр. huggingface) |
| Go-модули | точный путь `~/go/pkg/mod` | `go clean -modcache` (файлы read-only) с проверкой, что `go env GOMODCACHE` равен этому пути | повторная загрузка модулей |
| `~/.minikube/cache` | точный путь | содержимое | повторная загрузка образов при `minikube start` |
| Xcode DerivedData *(моё)* | `~/Library/Developer/Xcode/DerivedData` | содержимое | пересборка в Xcode |
| npm cache *(моё)* | `~/.npm/_cacache` | `rm -rf` каталога | повторная загрузка пакетов |
| Gradle caches *(моё)* | `~/.gradle/caches` | содержимое | повторная загрузка зависимостей, долгий первый build |
| Cargo registry *(моё)* | `~/.cargo/registry` | содержимое | повторная загрузка crates |

**Где ищутся `target` и `node_modules`** *(моё)*: только вне служебных мест — не внутри
`~/Library/**` и не внутри скрытых каталогов верхнего уровня домашней папки (`~/.*/**`: там
расширения VS Code/Cursor, плагины Claude Code, `~/.npm/_npx`, `~/.cargo/git/checkouts` — их
`node_modules`/`target` не восстанавливаются простым `install`/`build`). То же правило — в
`DeletionGuard`. Фиксированные категории из таблицы (`~/.cache`, `~/.cargo/registry` и т.д.)
перечислены явно и под это правило не попадают.

Уточнение по `node_modules`: проверяется только «у родителя есть `package.json`»; проверка
«внутри нет `.git`» — как у `target`. (`package.json` внутри самого `node_modules` бывает у
некоторых инструментов, поэтому это не признак корня проекта.)

Подпись строки: для `target`/`node_modules` — «Rust target · <имя родителя>», при совпадении
имён у разных строк видна полная `~/...`-строка пути во второй строке; для фиксированных —
путь `~/...`. Во второй строке: путь, «изменён N назад» (максимум mtime поддерева), цена.

В списке — категории от **100 МБ**; более мелкие сводятся в одну строку без чекбокса
«и ещё N мелких · X ГБ» *(моё)*. Сортировка по размеру. **По умолчанию ничего не отмечено**
*(моё: удаление необратимо)*.

### 5.6. Защита идущей сборки

1. На виду — «изменён 5 мин назад» по максимуму mtime поддерева.
2. Строка, изменённая менее **60 минут** назад, помечается «возможно, идёт сборка» *(моё)*;
   отметить её можно.
3. Для Rust `target` перед удалением проверяется **блокировка cargo**: cargo держит `flock` на
   `target/<profile>/.cargo-lock` всё время сборки. Перед запуском удаления для каждого
   `target/*/.cargo-lock` делается попытка `flock(LOCK_EX | LOCK_NB)` с немедленным
   освобождением; занято → путь исключается с причиной «идёт сборка cargo» *(моё)*. Проверка за
   протоколом, в тестах — фейк.

### 5.7. Удаление

1. «Очистить выбранное · N ГБ» (сумма отмеченного по последнему скану) → **лист подтверждения**
   (sheet, не alert, *моё*: в alert не помещается полный список) со всеми путями, размером
   каждого, итогом и текстом «Удаление сразу, без Корзины. Отменить нельзя.»; кнопки
   «Отмена» и деструктивная «Удалить · N ГБ».
2. **Перепроверка путей** (§5.8) — при открытии листа и ещё раз по нажатию «Удалить».
   Отвергнутые пути показываются в листе отдельно с причиной и не удаляются.
3. Запускается **одна** синтетическая `Command` с фиксированным UUID в пространстве
   `CleanupCommands` (входит в `allIDs` → блокирует все кнопки страницы, как docker-очистки),
   имя «Очистка: файлы Mac (N путей)». Скрипт — последовательность шагов, каждый со своей
   shell-проверкой (вторая линия защиты от подмены между проверкой и запуском):

   ```sh
   rc=0
   echo '→ /Users/u/work/grount/target'
   if [ -d '/Users/u/work/grount/target' ] && [ ! -L '/Users/u/work/grount/target' ] \
      && [ -f '/Users/u/work/grount/Cargo.toml' ]; then
     rm -rf -- '/Users/u/work/grount/target' || rc=1
   else echo 'skipped: no longer matches'; rc=1; fi
   echo '→ /Users/u/Library/Caches (contents)'
   if [ -d '/Users/u/Library/Caches' ] && [ ! -L '/Users/u/Library/Caches' ]; then
     find '/Users/u/Library/Caches' -mindepth 1 -maxdepth 1 -exec rm -rf -- {} + || rc=1
   fi
   echo '→ Go modules'
   if [ "$(go env GOMODCACHE)" = '/Users/u/go/pkg/mod' ]; then go clean -modcache || rc=1
   else echo 'skipped: GOMODCACHE differs'; rc=1; fi
   exit $rc
   ```

   Все пути — через `shellQuote`. Каждый шаг выполняется независимо от неудачи предыдущего.
4. Вывод — в «Логи» и в раздел «Последнее действие» (как сейчас). Частичная неудача (например,
   часть `~/Library/Caches` защищена системой) → состояние `failed`, лог показывает, что не
   удалось.
5. После завершения (любого): перечитать диск Mac; из результата скана убрать пути, которых
   больше нет, и вычесть их размер из родительских папок; оставшиеся (не удалились) — оставить
   с пометкой «размер мог измениться — пересканируйте». Сохранить обновлённый результат.

### 5.8. Перепроверка пути перед удалением (чистая функция за протоколом ФС)

Путь проходит, только если **всё** верно:

- абсолютный, стандартизованный, без `.`/`..`, начинается с `<home>/`; не равен `<home>`, `/`,
  `~/Library`, `~/work`-подобному корню — то есть путь ровно тот, что показан в категории;
- существует, это каталог, не симлинк (`lstat`);
- `realpath(path) == path` — ни один предок не симлинк наружу;
- тот же том, что у домашней папки (`st_dev`);
- всё ещё подходит под свою категорию (для `target` — у родителя файл `Cargo.toml`, внутри нет
  `Cargo.toml` и `.git`; для `node_modules` — у родителя `package.json`, внутри нет `.git`;
  для фиксированных — путь равен ожидаемому);
- не корень проекта: внутри нет `.git` (для фиксированных кешей не проверяется);
- для `target` — cargo-lock не занят (§5.6).

### 5.9. Крупнейшие папки

- Дети домашней папки от **1 ГБ** *(моё)*, по убыванию; остальное — строка «прочее · X ГБ».
- Строка каталога раскрывается (`DisclosureGroup`) на его детей из сохранённого дерева.
  Дерево хранит каталоги от **100 МБ** *(моё)*; мелкие дети сводятся в «прочее», чтобы
  `disk-scan.json` оставался небольшим.
- У каждой строки — кнопка «Finder» (`NSWorkspace.activateFileViewerSelecting`).
- Кнопок удаления у этих строк нет. Найденные категории внутри дерева помечаются подписью
  категории (удаляются только через «Можно очистить»).
- **Файлы дисков VM**: `~/.colima` (там `_lima/_disks/*/datadisk`) — строка с подписью
  «диск VM» и переходом (`FormNavigationRow`) к разделу Colima (прокрутка `ScrollViewReader`).
  `Docker.raw` лежит в непросканированном `~/Library/Containers`, поэтому такой строки для
  Docker Desktop нет. Сами файлы не удаляются отсюда.
- Недоступные каталоги — подпись «недоступно» вместо размера.

### 5.10. Разделы движков

Видимость по **установленности**, не по «активному движку»:

| Раздел | Виден, если | Запущен, если | Не запущен |
|---|---|---|---|
| Colima | `ColimaEngine.isInstalled()` | `ColimaEngine.isRunning()` | «не запущен» + размер диска VM на Mac, без docker-кнопок и без «Память VM» |
| Docker Desktop | `DockerDesktopEngine.isInstalled()` | `DockerDesktopEngine.isRunning()` | «не запущен» + «размер файла диска недоступен», без docker-кнопок |
| Minikube | бинарь `minikube` (`/opt/homebrew/bin`, `/usr/local/bin`) или `~/.minikube` | probe `minikube ssh` ответил | «не запущен», без кнопок |

**Colima** — как сейчас: `docker system df` внутри VM, test containers, оценки, три очистки,
полоса «Диск VM» (переезжает из шапки страницы в раздел Colima), «Память VM» и перезапуск, плюс
строка **«Файл диска VM на Mac»**: allocated size `~/.colima/_lima/_disks/<профиль>/datadisk` по
каждому профилю (на этой машине их три: `colima` 91 ГБ, `colima-krill-accept` 0.7 ГБ,
`colima-krill-fresh` 0.7 ГБ) с подписью, что место внутри VM освобождается, а файл на Mac не
сжимается (fstrim — не-цель). Стат файла — без процесса, за протоколом.

**Docker Desktop** — те же три очистки, test containers и `docker system df`, но docker CLI
запускается на Mac с `DOCKER_HOST=unix://$HOME/.docker/run/docker.sock`:
- команда: `env DOCKER_HOST="unix://$HOME/.docker/run/docker.sock" sh -c '<script>'`;
- probe: `/bin/sh -c <script>` с `DOCKER_HOST` в окружении процесса и Homebrew/Docker-путями в
  `PATH` (`/usr/local/bin`, `/opt/homebrew/bin`, `/Applications/Docker.app/Contents/Resources/bin`);
- строка «Файл диска VM на Mac» — **«размер недоступен»** с пояснением, что файл лежит в
  защищённых данных приложений (`~/Library/Containers/com.docker.docker/Data/vms/0/data/Docker.raw`),
  куда DevDeck не заходит без разрешения (решение пользователя, §8.1). Путь `Docker.raw` не
  стат'ится;
- полосы «Диск VM» и «Память VM» для Docker Desktop нет (нет df-probe; «Прочее» не считается);
- проверить вживую нельзя — только тесты с фейками; в отчёте так и сказать.

**Minikube** — как сейчас (`minikube ssh`), в заголовке — на чём живёт: драйвер из
`~/.minikube/profiles/minikube/config.json` (`Driver`), и движок: тот, в чьём `docker system df -v`
нашёлся том с меткой `created_by.minikube.sigs.k8s.io` (уже парсится как
`nestedDaemonVolumeBytes`). Пример: «minikube — внутри ноды · драйвер docker, в colima».
Не определилось — только драйвер. Сноска «освобождая здесь, освобождаете и диск <движок>» и
«Прочее» считаются от тома в найденном движке.

**Профили colima** *(моё)*: раздел Colima — про профиль по умолчанию (lima-инстанс `colima`),
к которому сейчас обращаются `colima ssh` и cleanup-команды. «Запущен» для раздела — живой
`ha.pid` именно этого инстанса (новый метод рядом с `ColimaEngine.isRunning()`, сам
`isRunning()` для трея/`EngineModel` не меняется). Строка «Файл диска VM на Mac» перечисляет
все профили из `_lima/_disks`. Раздел на каждый профиль — не делаем.

**Полоса «Диск VM», «Память VM» и «Прочее»** *(моё)*: берутся из существующих кешей
`ProcessManager` (`cachedVMDisk`, VM-сэмпл) с их текущими гейтами (настройка мониторинга VM,
активный движок, recovery). Нет данных → эти строки не показываются, остальное в разделе
работает. Своих probe в обход гейтов страница не заводит. «Память VM» и перезапуск видны, когда
запущен профиль colima по умолчанию.

`DockerHost`: `engineVM` переименовывается в `colima`, добавляется `dockerDesktop` **в конец**
`allCases` (`[colima, minikube, dockerDesktop]`), чтобы id существующих команд не сдвинулись.
Подписи разделов больше не зависят от «активного движка»: имя хоста фиксировано.
`EngineModel` (активный движок) остаётся для поповера и трея — страница от него больше не зависит,
кроме intro.

Что не меняется: оценки, test containers, `RowID` (теперь три хоста — уникальность
проверяется тестом раскладки), «Последнее действие», перезапуск colima (только в разделе Colima
и только когда colima запущена), отсутствие спиннера в toolbar.

## 6. Сценарии

1. **Первое открытие.** Видна полоса «Диск Mac», под ней «Ещё не сканировали — нажмите
   «Сканировать»». Ниже — Colima (запущена) и Minikube. Docker Desktop не установлен — раздела
   нет.
2. **Скан.** «Сканировать» → прогресс растёт; «Остановить» → через доли секунды прогресс пропал,
   на экране прежний результат или снова «ещё не сканировали».
3. **Результат.** Видны категории ≥ 100 МБ без отметок, у `guild/target` — «изменён 5 мин назад —
   возможно, идёт сборка»; крупнейшие папки; `~/.colima (диск VM)` ведёт к разделу Colima.
4. **Перезапуск приложения.** Результат с датой сканирования на месте.
5. **Удаление.** Отметил два `target` и `~/.cache` → «Очистить выбранное · 212 GB» → лист
   с тремя путями и итогом → «Удалить» → кнопки страницы заблокированы, лог идёт в «Последнее
   действие» → по завершении строки пропали, полоса «Диск Mac» обновилась.
6. **Сборка идёт.** Отмечен `target`, у которого занят `.cargo-lock` → в листе он в «Пропущено:
   идёт сборка cargo», остальное удаляется.
7. **Подмена.** Между сканом и удалением `target` заменили симлинком или удалили `Cargo.toml` →
   путь отвергнут в листе; если подмена случилась уже после проверки — shell-проверка шага
   пропускает его, лог «skipped», состояние `failed`.
8. **Недоступная папка.** Каталог с EACCES → «частично: 1 папка недоступна», раскрытие показывает
   путь.
9. **Colima остановлена.** Раздел Colima: «не запущен», размер файла диска VM; ни docker-кнопок,
   ни «Памяти VM».
10. **Docker Desktop установлен и запущен** (только тестами) — раздел с цифрами и кнопками, команды
    с `DOCKER_HOST`.

## 7. Оставлено на усмотрение исполнителя

- `getattrlistbulk` или `opendir`+`lstat` в live-чтении каталога (по замеру на реальной домашней
  папке; семантика §5.4 обязательна).
- Точная форма модели результата и формат `disk-scan.json` (с полем версии, чтобы старый файл
  тихо игнорировался).
- Как пробрасывать прогресс (`AsyncStream`, колбэк с троттлингом) — главное, не чаще ~4 раз/с и
  без блокировки главного актора.
- Мелкая раскладка строк в рамках стиля «General».

## 8. Открытые вопросы к пользователю

### 8.1. Папки, на которые macOS показывает окно-запрос — решено

Вопрос: заходить ли в Desktop / Documents / Downloads / iCloud Drive / данные других приложений
(`~/Library/Containers`, `~/Library/Group Containers`), где macOS при первом входе спрашивает
разрешение. **Решение пользователя: не заходить.** Эти папки помечаются «не просканировано —
защищено macOS»; размер `Docker.raw` не читается («размер недоступен»). См. §5.4, §5.9, §5.10.

Открытых вопросов больше нет.

## 9. План задач

Каждая задача — TDD: сначала тест на фейке (probe pattern), потом код. Набор тестов запускается
`DEVELOPER_DIR=/Applications/Xcode.app xcodebuild test -project DevDeck.xcodeproj -scheme DevDeck
-destination 'platform=macOS'` (по одному классу — `-only-testing:DevDeckTests/<Class>`).

1. **Чтение ФС и сканер.** `DirectoryReading` (протокол: список записей каталога с типом,
   allocated size, dev, ino, nlink, mtime; ошибка доступа отдельно), live-реализация,
   `DiskScanner` (обход: симлинки, том, hardlink, недоступное, mtime поддерева, отмена,
   прогресс, пропуск защищённых папок). Тесты на фейковом дереве: сумма, hardlink один раз,
   защищённые папки не читаются вовсе, симлинк не разворачивается,
   другой dev не обходится, EACCES → частично, отмена прерывает, mtime — максимум.
2. **Категории.** Чистая функция распознавания + правило «внешняя побеждает», порог 100 МБ и
   свод мелких. Тесты на все строки таблицы §5.5 и отрицательные случаи (`target` без
   `Cargo.toml`, `target` с `Cargo.toml` внутри, вложенный `node_modules`, `target` в `~/.cache`,
   `node_modules` в `~/.vscode/extensions/…` и в `~/Library/Application Support/…`).
3. **Перепроверка путей.** `DeletionGuard` за протоколом (`lstat`, `realpath`, dev, существование
   соседей, cargo-lock). Тесты на каждое правило §5.8 (симлинк, симлинк-предок, вне home, `~`,
   `/`, другой том, категория больше не подходит, `.git` внутри, занятый lock).
4. **Команда удаления.** Построение скрипта §5.7 (`shellQuote`, shell-проверки по категории,
   `go clean -modcache` с проверкой `GOMODCACHE`, содержимое vs каталог, `rc`), фиксированный id
   в `CleanupCommands.allIDs`. Тесты на строку команды (включая путь с `'` и пробелами).
5. **Хранение результата.** `DiskScanStore` (0600 через `PrivateFile`, версия, битый файл →
   nil); вычитание удалённых путей из дерева. Round-trip тест во временном каталоге.
6. **`DiskOverviewModel`.** Скан/отмена/прогресс/сохранение, взаимоисключение со всеми
   cleanup-командами, выбор, сумма, подтверждение → перепроверка → `manager.run`, пересчёт после
   завершения; диск Mac через `VolumeUsageProbing`. Тесты с фейками ФС и `FakeCommandRunner`.
7. **Хосты и движки.** `DockerHost` `[colima, minikube, dockerDesktop]`, `wrap` и probe-вызов
   Docker Desktop с `DOCKER_HOST`, «запущен» для профиля colima по умолчанию, присутствие minikube, драйвер из `config.json`, «на каком
   движке живёт minikube», видимость разделов по installed/running, размер файлов дисков VM
   (`FileSizeProbing`). Тесты: строки команд, видимость для всех сочетаний, существующие id
   colima/minikube не изменились, парсинг драйвера.
8. **UI.** `CleanupView`: раздел «Диск Mac», «Можно очистить», «Крупнейшие папки», sheet
   подтверждения, toolbar «Сканировать/Остановить», переходы к разделам движков, разделы
   Colima / Docker Desktop / Minikube; L10n EN/RU. Расширить `CleanupLayoutTests` (три хоста,
   уникальность `RowID`, кнопки внутри карточек), wiring в `AppDelegate`.
9. **Проверка в dev-сборке** (`scripts/run-development.sh`): реальный скан домашней папки
   (только чтение) — прогресс, отмена, категории, раскрытие, Finder, подтверждение (до «Отмена»).
   Реальное удаление — только тестового дерева: для этого DEBUG-only аргумент
   `--dev-scan-root <path>` *(моё)* подменяет корень сканирования (и «домашнюю папку» для
   перепроверки) на каталог в scratchpad с фейковыми `proj/Cargo.toml` + `proj/target/…`. В
   Release аргумент не существует.
10. **Ревью и коммит.** revust code review с профилем проекта без изменений (сначала dry-run), до 2
    раундов; находки проверить по коду, исправления — в этой ветке; локальный коммит без
    атрибуции.
